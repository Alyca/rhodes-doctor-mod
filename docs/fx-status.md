>
> **① 离线选材**（`blueprints.zip`，不用进游戏试）：`Shape` 必须 `Cylinder`（`Wall` 是直线墙拼不成圆）；

>
> **③ 要改色就克隆重染**：`area.Fx` 是引擎直接播的 PrefabLink，改不了色；原版也没有天然是"苍白石壳"色的素材。
>
> 用 `AreaGroundFx.Register(区域GUID, 素材, 目标色, textureLift, scale)`，跟区域同生同灭（做法与 SmokeFx 同源，已做成注册表）。
>
> **④ 染色坑共八条**（详见 `dev-notes.md` §7.11.5）：屏幕色 ≈ **tint 的 2~3 次幂**（想浅要往白里给）；

>

### 借素材 / 自绘手法要点（详见 `fx-plan.md` 与 `dev-notes.md` §7）

- **整片爆发** → 借原版法术的 `AbilitySpawnFx` 或区域的 `Fx`（`FxLibrary` / `FxBorrow`）。
- **单个物件**（剑 / 石头 / 柱）→ 借 `BlueprintWeaponType.VisualParameters` 的武器**网格**（`FxBorrow.WeaponModelFx`）。
- **细长 / 很小的装饰**（光尾 / 光点 / 光圈）→ **自己画**（`TrailRenderer` / `LineRenderer` / 自建面片）；  
  粒子素材缩不小，别借。
- **既要"常驻跟随"又要改形状/改色** → 也可整份自绘 + 订阅 `IUnitBuffHandler` 跟增益同生同灭：
  例：战术标记的「战术投影」（`TacticalProjectionFx`，10-16）、重构 / 文明的存续（`MassRestoreFx`）。
  材质一律复用 `SwordStreakFx.StreakMaterialPlain`（剑雨 / 重构实机验证能上屏），**不用 `Shader.Find`**。
  **10-16 起"敌方标记类"有现成可复用件**：`src/MarkFxKit.cs`（`MarkFxTracker` 管生命周期 / `MarkFxBase` 管跟随+淡出+每秒自检 /
  `MarkFxKit` 管 `LineRenderer` 管线件）——火力侦察、终末狙击在用；再加一个"标记类"特效只需写 `Build` + `Tick` 两个方法。
- ⚠ **"个人距离 + 自扫"的法术，视觉动作要挂在「能力自己的效果动作」上**：在 `SpellsSetup` 里写
  `effects.Add<ContextActionXXX>()`（`effects` 就是 `ability.AddAbilityEffectRunAction(effects)` 那一份）。
  **不要**用 `AdditionalAbilityEffectRunActionOnClickedTarget` —— 它是"**点击目标**时执行"，
  对个人距离法术不触发（与 `AbilitySpawnFx` 那条老坑同源）；也**不要**图省事挂增益的 `activated`，
  那会在读档重新激活增益时再演一次。
  已验证的先例：**重构 / 文明的存续**（`Range=Personal`，`ContextActionMassRestore`，作者已确认上屏）。
  ⚠ **但"要持续一整分钟"的就不能走这条**（能力动作只跑一次）：**战场测绘** 10-16 最终改成
  **跟增益常驻**——由 `MarkFxTracker` 订阅它自己的增益（增益在就在），见下一条。
- ⚠ **"要跟增益同生同灭 / 持续到增益结束"的视觉，一律走 `MarkFxTracker`**（`src/MarkFxKit.cs`）：
  订阅 `IUnitBuffHandler` + 按增益名/GUID 过滤，**时长由增益自己决定**（战场测绘 = 10 轮 = 1 分钟，
  不用把 60 秒写死；改轮数也不用动特效代码），增益到期 / 被驱散 → 0.3 s 淡出，另有"每秒自检增益还在不在"兜底。
  接线三处：新建 `Tracker`（名字 + `Guids.Buff(下标)` 兜底）→ `MarkFxWatcher` 的两个 handler 各加一行 →
  **特效类继承 `MarkFxBase`**，只写 `Build`（建线）+ `Tick`（每帧摆位）。先例：火力侦察、终末狙击、战场测绘。
  ⚠ 走这条路就**不要再在能力动作里触发**（会生成第二份特效）。
- ⚠ **自绘线的"线宽"要按屏幕像素估，不能只看米数**：`StreakMaterialPlain` 是**软边贴图**
  （`sin²` 横跨带宽），**有效亮芯只有宽度的 ~1/3**。实战教训（10-16 战场测绘）：同样是 3.5 cm 的线，
  在 **1.9 m** 处看得见、在 **9.1 m** 处就是亚像素 —— 30 尺边界虚线环整圈"没上屏"（作者："1.5 秒后我虚线都没看到"）。
  ⇒ **远处的环 / 圈一律给 0.12~0.16 m 以上，并配足 alpha（0.9 左右）**；近处的小圈才用 0.03~0.05。
- **"当前全部单位"一律走 `UnitScan.Take()`**（`src/UnitScan.cs`）：它 = `Game.Instance.State.Units` ∪ 跨场景队伍 ∪ Party，
  且挡掉 `Descriptor == null` 的半成品单位（直接遍历 `State.Units` 时那种单位会让整个动作抛异常）。
  ⚠ 池子是**全局**的 → 调用方必须自己做距离**和同场景**筛选（`u.HoldingState == caster.HoldingState`），
  否则别的区域残留的单位可能在**世界坐标**上撞进范围。
- 尺寸：`Shape=Cylinder` 区域的 `Size` 是**半径（尺）**；竖向物件用 `FitLongestMeters`；`Renderer.bounds` 不可信。
- 自建材质**一律克隆原版 FX 材质**（`SwordStreakFx.MaterialFor`），`Shader.Find` 只作兜底。

### 复核方法（可复用）

`blueprints.zip` 里可直接读每个原版蓝图的 `Data` 字段，判断某法术有没有 `AbilitySpawnFx`、  
某区域有没有 `Fx`，比进游戏试快得多。另见 `dev-notes.md` 第 0 节。  
离线工具：`python tools/scan_buff_fx_all.py [关键字...]`（全库扫有 `FxOnStart` 的 buff）。

### buff 显示名（2026-10-10 全模组修正）

- **问题**：`CreateExtraBuff` 默认把 buff 的**显示名 / 说明设成法术名与法术描述**（`s.Name` / `s.Desc`）。
  结果敌人身上出现一堆**同名 buff**（比如两条都叫「梦魇」），玩家认不出那是「惊惧 / 动摇」这类状态（作者截图反馈）。
- **排查**：扫 `SpellsSetup.cs` 全部 `CreateExtraBuff(...)`，显示名用 `s.Name` 的共 **23 个**；
  已全部改成 `L10n.S("spell.<法术>.<状态>.name", "…")` 专属状态名（如 火山（余焰）/ 冰封领域（定身）/ 连锁殉爆（标记））。
- **⚠ 本地化坑**：`L10n.S(key, zh, en)` **运行时只返回键**，字符串本体在 **`LocalizedStrings.json`（手工维护、无生成脚本）**。
  改了代码没加 JSON 键 → 游戏显示 `[unknown key: rhodesdoctor.xxx]`（看着像乱码）。
  **凡改 `L10n.S`，必须同步往 `LocalizedStrings.json` 加 `{Key, zhCN, enGB}`。** 本次共 **+27 条键**（244 → 271）。
- **可复用校验**：把 `src/*.cs` 里所有 `L10n.S("…")` 键与 JSON 的 `Key` 逐个比对，缺一个都会暴露（本轮校验结果：251 个代码键全在，缺失 0）。
